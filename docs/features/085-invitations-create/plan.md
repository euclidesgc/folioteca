Ambiente: Node 24, pnpm 11, TypeScript 5.9 strict, Prisma 6, NestJS 11, Vite 8, React 19, Vitest com os projetos `api` e `web`, Playwright.

Comandos de verificação, sempre na raiz e sempre a suíte inteira: `pnpm install`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`. "Sem aviso" vale para os cinco. ## Regras que valem para todas as tarefas

- **Nenhuma dependência nova** em nenhum `package.json`; `pnpm-lock.yaml` não muda.
- **A migration desta fatia é escrita à mão** e aplicada por `prisma migrate deploy` (é o que `apps/api/test/global-setup.ts` já roda antes dos testes). Ninguém — agente, teste ou critério — roda `prisma migrate diff`, `prisma migrate dev` nem `prisma migrate reset`. Os únicos subcomandos permitidos são `pnpm --filter api exec prisma validate`, `pnpm --filter api exec prisma migrate status` e `pnpm --filter api exec prisma migrate deploy` (contra `postgresql://folioteca@localhost:5433/folioteca_test`). A limpeza entre testes da API é `resetDatabase(prisma)`.
- Todo componente devolve `React.JSX.Element` (nunca o `JSX` global); `ref` é prop comum (sem `forwardRef`); **todo botão nosso é o componente `Button`** de `apps/web/src/components/ui/button/button.tsx`; imports absolutos com `@/`; sem barrel files; arquivos em kebab-case. Textos de tela em pt_BR; código, comentários, caminhos de URL e nomes de teste em en_US.
- Nenhum `eslint-disable` sem `-- <motivo>`. Nenhum segredo em variável `VITE_*`; nenhum token em `localStorage`; **nenhum literal com cara de senha, token ou hash em arquivo versionado** (o GitGuardian reprova o push): o token da API simulada é montado em tempo de execução, como o `MOCK_PASSWORD` já faz. Sessões de teste da API vêm de `createPersonWithSession` (`apps/api/test/create-person.ts`) ou dos ajudantes já usados no arquivo; id inválido é `randomUUID()` ou `'nao-e-uuid'`.
- Cobertura ≥ 80% de linhas **por arquivo** novo ou alterado. Não contam arquivos só de tipos, arquivos com 0 de 0 linhas instrumentáveis, nem os já excluídos pelo `vitest.config.ts` da raiz (`**/types/**`, `**/generated/**`, `**/src/testing/**`, `**/test/**`, `**/*.config.*`). Nenhuma exclusão nova.
- **Toda** espera logo após mudança de rota ou chunk `lazy` tem timeout explícito: nos testes da web pela constante `LAZY_TIMEOUT` declarada no arquivo (`findBy…(…, {}, LAZY_TIMEOUT)`, `waitFor(…, LAZY_TIMEOUT)`); no e2e pela constante `ROUTE_TIMEOUT` declarada no topo do spec. Nunca `setTimeout`/sleep fixo nem `waitForTimeout`. Tecla de movimento (`Tab`, setas) seguida de tecla de edição (`Enter`, `Espaço`, `Escape`) só depois de esperar (`expect(...).toHaveFocus()` / `toBeFocused()`) a seleção assentar.

- Testes de API são de integração contra o Postgres real (padrão `apps/api/test`); "teste passa" é medido pelo **exit code** de `npx vitest run --project api` / `--project web` (zero), nunca pela leitura da saída `--verbose`.
- O agente derruba tudo o que subir (servidores, watchers) ao fim da tarefa. Cada fase termina com **um** commit Conventional Commits em inglês (`feat:`, `test:`, `docs:`), sem `--no-verify`.
- Nenhuma tarefa acrescenta escopo: sem `GET /invitations`, sem aceitar, revogar ou enviar e-mail; sem coluna `acceptedAt`/`revokedAt`; sem extrair `hashToken` ou schema de e-mail para `common/`; sem store Zustand para o token; sem modal para o link; sem limitação de taxa.
