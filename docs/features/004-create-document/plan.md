# PLAN 004 — create-document

Branch: `feature/004-create-document` (sai de `feature/003-login-logout`, que é a base real; toda comparação de "arquivo intocado" é contra ela, nunca contra `develop`).

Fonte: `docs/features/004-create-document/spec.md` (as siglas D1…D15 são as decisões técnicas da SPEC e R1…R10 os requisitos do PRD; o texto necessário de cada uma está copiado na tarefa). Ambiente: Node 24, pnpm 11, TypeScript 5.9 strict, Prisma 6, NestJS 11 com SWC, Vitest com os projetos `api` e `web`, Playwright.

Pré-condição de todas as fases: `docker compose up -d` na raiz (Postgres local). Comandos de verificação, sempre na raiz e sempre a suíte inteira: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`. "Sem aviso" vale para os quatro. O aviso de desempenho que o próprio Vitest imprime sobre o ambiente jsdom é da ferramenta e **não conta**.

Regras que valem para todas as tarefas:

- Nenhum literal com cara de senha, token ou hash em arquivo versionado (o GitGuardian reprova). O que precisar é montado em execução (`randomUUID()`, constantes de `apps/web/src/testing/mocks/utils.ts`).
- Todo componente devolve `React.JSX.Element` (nunca o `JSX` global); `ref` é prop comum (sem `forwardRef`); **todo botão é o componente `Button`** de `apps/web/src/components/ui/button/button.tsx`, inclusive "Tentar novamente"; navegação interna é `<Link>`/`<NavLink>` do roteador; imports absolutos com `@/`; sem barrel files; arquivos em kebab-case.
- Banco: a migration desta fatia é **escrita à mão** e aplicada por `prisma migrate deploy` (o `global-setup` dos testes da API já faz isso no banco de teste). Ninguém — agente, teste ou critério — roda `prisma migrate diff`, `prisma migrate reset` nem `prisma migrate dev`. A limpeza entre testes é `resetDatabase(prisma)` de `apps/api/test/reset-database.ts`.
- Cobertura ≥ 80% de linhas **por arquivo** novo ou alterado. Não contam arquivos só de tipos nem os excluídos do relatório pelo `vitest.config.ts` da raiz (`**/types/**`, `**/generated/**`, `**/src/testing/**`).
- A fatia já está acima do teto de tamanho (decisão registrada na SPEC, aceita): nenhuma tarefa acrescenta escopo. Sem conteúdo do documento, favorito, lixeira, compartilhamento ou paginação.
- Toda decisão de acesso é do servidor. A web não filtra documento nenhum nem ramifica por `accessLevel`.

Desvios em relação à tabela de arquivos da SPEC, sem mudar escopo:

1. `docs/design.md` sai da fase 3 e entra na fase 2 (T2.4 e T2.5): a skill `interface-design` manda a receita nova entrar na mesma entrega da tela que a usa, e os critérios visuais da fase 2 apontam para ela.
2. O caso "o link da barra lateral de Meus documentos fica marcado como página atual", que hoje vive em `empty-areas.test.tsx`, passa para `my-documents.test.tsx` (T2.7), para não se perder quando "Meus documentos" sair do conjunto de áreas vazias fixas.
3. `formatDateTime` devolve texto vazio para data inválida (o `Intl.DateTimeFormat` lança `RangeError`; uma data ruim não pode derrubar a lista). A SPEC não tratou o caso.
