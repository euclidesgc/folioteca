# Registro 2026-09-02-002 — A fronteira de agent abria com plugin desatualizado

**Sessão:** 2026-09-02 · **Item(ns):** `001-esqueleto-do-monorepo` · **Fases:** 2

Não é proposta: o harness já corrige isto na `0.2.1`. Este arquivo existe para
explicar por que a `tool-matrix.json` deste projeto tem chaves prefixadas e por
que `scripts/gates/__tests__/fronteira-de-agent.test.sh` foi escrito.

---

## O que aconteceu

O `doc-reconciler` foi despachado para reconciliar um documento aprovado — o
caso exato que o guard existe para permitir — e foi recusado dizendo que quem
faz aquilo é o `doc-reconciler`.

A causa: `_hooklib.active_agent` devolvia o `agent_type` do evento verbatim, e o
Claude Code namespaceia agent de plugin (`harness:doc-reconciler`). As
comparações a jusante eram por igualdade nua. O mesmo desencontro falhava para
os dois lados:

| Comparação | Efeito |
|---|---|
| `agent == "doc-reconciler"` em `guard_write.py` | reconciler nunca reconhecido — falha fechado |
| `matrix["agents"].get(agent)` nos dois guards | sem política → libera — falha aberto |

Medido com o evento real alimentado aos hooks da `0.1.0`, os nove agents do
plugin escreviam em qualquer caminho e delegavam à vontade:

```
harness:scout      Write em apps/api/src/main.ts   -> allow   (deveria negar)
harness:scout      Task para outro agent           -> allow   (deveria negar)
harness:doc-writer Write em apps/web/src/x.ts      -> allow   (deveria negar)
```

Os cinco agents locais do projeto nunca foram afetados: o nome deles chega nu e
casa com a matriz.

## Por que não virou proposta

O harness resolve isto na `0.2.1`, em duas frentes, e a docstring de
`_hooklib.normalize_agent` nomeia este projeto como o caso que a motivou:

- `active_agent` normaliza a identidade, descartando o prefixo do plugin;
- o carregador da matriz normaliza também as **chaves**, então as duas grafias
  são encontradas.

O que este projeto viveu foi executar a `0.1.0` do cache enquanto a `0.2.1` já
estava instalada — atualização de plugin só vale na sessão seguinte.

## O que fica no projeto

`.harness/tool-matrix.json` tem as nove chaves do plugin prefixadas. Sob a
`0.2.1` isso é redundante, não errado: o carregador normaliza as duas formas.
Voltar ao nome nu é cosmético e não urge.

`scripts/gates/__tests__/fronteira-de-agent.test.sh` afirma a simetria que teria
pegado o defeito — chave nua nomeia agent local, agent local tem chave nua — e
roda no fluxo `Portões`, que existe para portão que parou de morder. Ele
continua valendo, porque o que ele guarda não é a grafia da chave: é que nenhuma
chave da matriz aponte para agent nenhum. Uma fronteira que abre por diferença
de grafia não é fronteira, e uma que abre em silêncio é pior.
