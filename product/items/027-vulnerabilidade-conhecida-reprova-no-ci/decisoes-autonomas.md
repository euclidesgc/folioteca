| D11 | brief | **O merge deste PR esbarrou num defeito da tranca, e o conserto virou o PR #32, irmão deste e não empilhado sobre ele** | Empilhar o conserto sobre este PR; ou registrar item de roadmap e mergear por outra via | `scripts/merge-se-liberado.sh 31` mediu tudo, liberou, e o `gh stack merge` recusou: `#31 is not a stack number or a stacked pull request`. A causa é o predicado — `gh stack view` responde pela pilha **local**, que existe a partir de uma branch, e a pilha do GitHub só nasce a partir de dois PRs, então todo PR sozinho caía na via que o GitHub recusa. Empilhar o conserto sobre este PR faria a pilha passar a ter dois PRs e o defeito sumiria por acidente, sem nunca ser testado no caso que o produz; um item de roadmap seria inventar futuro para o que fecha agora, contra a orientação da corrida. O PR irmão mantém os escopos separados — este é `docs`, aquele é `fix` — e o merge dele é a própria prova da correção, porque ele também é um PR sozinho numa pilha. | D12 | brief | **O merge falhou uma segunda vez, e o PR #32 passou a consertar a classe: a tranca mede todas as pré-condições do merge, e a corrida submete com `gh stack submit --open`** | Marcar este PR como pronto com `gh pr ready` e seguir, que resolvia a noite | Com a via corrigida, o merge foi recusado de novo — `Pull Request is still a draft`, porque `gh stack submit` cria rascunho quando o terminal não é interativo, que é o da corrida.
