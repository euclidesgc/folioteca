# D-017 — O critério comportamental do cliente divergente não morde: o gerador desfaz o "Dado" antes do diff

- **Fase:** 5 · **Detectada por:** execução do próprio critério · **Data:** 2026-09-03
- **Tipo:** `normal`
- **Afeta:** `03-plan.md` Fase 5, critério comportamental de RF-10.1 e RF-10.2

**Os docs dizem:**

*Dado* a linha `export type Divergente = string;` acrescentada ao fim de
`apps/web/src/shared/api/generated/types.gen.ts`, *quando*
`pnpm --filter web run api:generate && git diff --exit-code apps/web/src/shared/api/generated`
é executado na raiz, *então* o comando termina com código diferente de zero e a
saída contém `Divergente`.

**A realidade impõe:**

Executado exatamente assim, o comando termina com **0** e a saída **não** contém
`Divergente`:

```
EXIT=0
ocorrências de "Divergente" na saída: 0
```

A razão é o gerador. `openapi-ts` reescreve `types.gen.ts` inteiro, então a linha
acrescentada é apagada pelo primeiro comando do par; o `git diff` que vem depois
compara a árvore de trabalho com o índice, e o índice nunca teve a linha. Não
sobra diferença para acusar.

O critério irmão de RF-09 não sofre disso porque o "Dado" dele mexe no
código-fonte — o controller —, e o artefato gerado a partir dele muda de
verdade. Aqui o "Dado" mexe no próprio artefato que o gerador sobrescreve.

O mecanismo que o requisito cobra **funciona**. O que falta ao critério é
colocar a linha onde o CI a encontraria: no que foi commitado. Registrando a
linha no índice — que é o estado de um checkout — o mesmo comando morde:

```
EXIT=1
ocorrências de "Divergente" na saída: 1
```

**Opções:**

- **(a) Corrigir o "Dado" para registrar a linha no índice** (`git add` do
  arquivo depois de acrescentá-la), deixando o "Quando" e o "Então" como estão.
  Custo: reconciliar `03-plan.md` no mesmo PR. O critério passa a reproduzir o
  estado que o CI tem depois do checkout, que é o cenário que RF-10 descreve.
- **(b) Trocar o "Quando" por `git diff --exit-code HEAD -- <caminho>`.**
  Também morde, mas mede contra o commit em vez de contra o índice, e o comando
  deixa de ser o mesmo que o job do CI executa — dois textos que precisam ser
  mantidos iguais e não são.
- **(c) Deixar como está e reprovar a fase.** O critério continuaria medindo o
  gerador em vez do portão, e a próxima sessão gastaria o ciclo inteiro
  perseguindo um defeito que não existe no código.

**Recomendação:** (a). É a correção mínima, mantém o comando idêntico ao que o
job `contrato` roda e devolve ao critério a propriedade de reprovar quando o par
está fora de sincronia. Descartei (b) porque duplica a definição do comando em
dois lugares, e (c) porque manda o trabalho seguinte caçar um defeito
inexistente.
